Cómo aprende un LLM: next-token prediction, Cross Entropy, backpropagation y AdamW

Un Transformer no aprende porque alguien le explique qué significa un texto. Aprende ajustando sus parámetros para elevar la probabilidad del siguiente token observado. Seguiremos ese proceso desde la alineación entre inputs y targets hasta la actualización de pesos, y mediremos qué cambia al modificar el learning-rate schedule.

La pregunta central

Tenemos una secuencia de tokens y un modelo que produce logits para cada posición. ¿Cómo convertimos esa salida en una señal de aprendizaje, cómo llega esa señal a cada parámetro y cómo decidimos cuánto modificarlo en cada update? Separaremos el objetivo estadístico, la derivación del gradiente y la política de optimización.

1. Qué significa que un LLM aprenda

En un decoder-only language model, el entrenamiento habitual consiste en modelar la probabilidad de una secuencia como una cadena de predicciones condicionadas por el prefijo. El modelo recibe tokens previos y estima una distribución para el siguiente. Durante el pretraining, los propios textos aportan los targets: no es necesario que una persona etiquete manualmente cada token siguiente.

La arquitectura Transformer del capítulo 01 y la operación de self-attention del capítulo 02 ya están construidas. Aquí tratamos sus pesos como parámetros θ. Aprender consiste en encontrar valores de θ que reduzcan una función objetivo sobre ejemplos de entrenamiento. El optimizador no introduce conocimiento externo: transforma gradientes en actualizaciones de parámetros.

Conviene separar tres capas de razonamiento:

  • Objetivo: qué probabilidad queremos aumentar o qué error queremos reducir.
  • Gradiente: cómo cambia el objetivo cuando modificamos cada parámetro.
  • Optimizador: cómo combina gradientes, learning rate, estado histórico y regularización para producir un update.

2. Next-token prediction: el objetivo autoregresivo

Sea una secuencia tokenizada x₁, x₂, …, xT. La regla de la cadena permite factorizar su probabilidad conjunta:

pθ(x1, ..., xT) = ∏t=1..T pθ(xt | x1, ..., x(t-1))

El modelo aprende a asignar probabilidad al token real condicionado por el prefijo. Maximizar la probabilidad de la secuencia equivale, en su forma negativa, a minimizar la negative log-likelihood (NLL):

L(θ) = - Σt log pθ(xt | x<t)

Para optimizar minibatches y comparar longitudes, lo habitual es promediar sobre las posiciones objetivo válidas. La reducción mean produce una pérdida media por token, no la suma de todas las pérdidas del batch.

Esta formulación es la base del causal language modeling. El modelo debe construir una distribución sobre el vocabulario y recibe una señal mayor cuando el token observado obtiene poca probabilidad. La capacidad posterior de resolver tareas con prompts es una cuestión distinta de la definición del objetivo de pretraining.

3. Shift de inputs y targets: el detalle que no puede fallar

Considera el texto tokenizado como:

tokens:  [La, atención, mezcla, información, .]
input:   [La, atención, mezcla, información]
target:  [atención, mezcla, información, .]

La misma secuencia proporciona varios ejemplos de entrenamiento. En la posición 0 el modelo predice el token 1; en la posición 1 predice el token 2, y así sucesivamente. Input y target tienen la misma longitud tras desplazar una posición, pero no contienen los mismos IDs en la misma posición.

input_ids = batch[:, :-1]   # [B, T]
targets   = batch[:, 1:]    # [B, T]
logits = model(input_ids)   # [B, T, vocab_size]

El modelo procesa el prefijo conocido para cada posición. Gracias al causal masking, el estado de la posición t no puede consultar tokens posteriores, aunque el entrenamiento calcule las salidas de todas las posiciones del bloque en paralelo. Esta combinación aporta eficiencia sin permitir que la respuesta futura se filtre hacia la predicción.

Teacher forcing no equivale a fuga de futuro

Durante training, cada posición recibe el prefijo correcto del corpus, no las predicciones muestreadas previamente por el modelo. Eso se denomina habitualmente teacher forcing. La máscara causal sigue siendo imprescindible: sin ella, una posición podría consultar tokens que deberían ser desconocidos al predecir. En inference, el token generado se incorpora al contexto para producir el siguiente.

Un error de una sola posición altera todo el objetivo: si se compara cada logit con el token que ya estaba en su propia posición, el modelo aprende otra tarea. El test de alineación del laboratorio comprueba este desplazamiento antes de entrenar.

4. Logits y Cross Entropy: medir la predicción

La última proyección del modelo produce un vector de puntuaciones para cada token del vocabulario. Son logits, no probabilidades. Para una posición, z ∈ ℝᴠ, donde V es el tamaño del vocabulario. Softmax transforma esos scores en una distribución:

p_i = exp(z_i) / Σj exp(z_j)

Si el target correcto es la clase y, la Cross Entropy para esa posición es:

CE(z, y) = -log(softmax(z)[y])
         = -z_y + log(Σj exp(z_j))

La segunda expresión importa por estabilidad numérica: la implementación puede calcular log-softmax mediante técnicas como log-sum-exp, sin materializar una probabilidad diminuta y tomar después su logaritmo. Por eso torch.nn.CrossEntropyLoss espera logits sin normalizar. Aplicar softmax antes cambia la escala y la semántica de la pérdida; no lo hagas.

loss = F.cross_entropy(
    logits.reshape(-1, vocab_size),
    targets.reshape(-1)
)

Con logits [B, T, V] y targets [B, T], se aplanan batch y secuencia para tratar cada una de las B × T posiciones como una clasificación sobre V clases. En batches con padding, los targets de posiciones no válidas deben excluirse mediante ignore_index o una máscara equivalente. No basta con ignorar el padding en la atención si sigue entrando en la media de la loss.

Qué significa realmente una loss menor

La Cross Entropy penaliza mucho las predicciones que asignan poca probabilidad al target real. Si el modelo asigna 0,8 al token correcto, la pérdida es −log(0,8), aproximadamente 0,223. Si asigna 0,01, la pérdida sube a aproximadamente 4,605. El modelo no tiene que acertar siempre el argmax para obtener una loss útil: la función también mide la confianza relativa que asigna al target correcto.

La media de NLL en logaritmos naturales se relaciona con perplexity mediante:

perplexity = exp(mean_negative_log_likelihood)

Perplexity es una transformación exponencial de la loss, no una medida directa de comprensión. Su valor depende del tokenizer, del conjunto de evaluación, de cómo se cuentan los tokens y del dominio. No es válido comparar sin más una perplexity character-level con otra subword-level.

5. El gradiente de Cross Entropy: la señal por logit

Para una posición y una Cross Entropy estándar, la derivada respecto a los logits tiene una forma especialmente intuitiva. Si p es el vector softmax e y es el índice del target:

∂L/∂z = p - one_hot(y)

Cuando se promedia sobre N posiciones, el gradiente también queda dividido por N. En la coordenada del target se resta uno a la probabilidad predicha; en las demás coordenadas permanece la probabilidad estimada. El resultado empuja el logit correcto hacia arriba en relación con el resto.

Esta derivada es solo el primer tramo del backward pass. Los logits dependen de la proyección de salida; esta depende de las representaciones ocultas; y esas representaciones atraviesan normalizaciones, residuals, MLPs y atención. La regla de la cadena propaga la señal hacia cada matriz y embedding que participó en el forward pass.

El laboratorio genera logits sintéticos en float64, calcula la derivada con autograd y la compara con la expresión manual. El error absoluto máximo observado es 1,39 × 10⁻¹⁷, compatible con redondeo de punto flotante para esa prueba.

6. Backpropagation: del error a los parámetros

Autograd construye durante el forward pass un grafo de operaciones diferenciables. Al llamar a loss.backward(), PyTorch ejecuta reverse-mode automatic differentiation y acumula en parameter.grad la derivada de la pérdida respecto a cada parámetro que requiere gradiente.

optimizer.zero_grad(set_to_none=True)
logits = model(input_ids)
loss = F.cross_entropy(
    logits.reshape(-1, vocab_size),
    targets.reshape(-1)
)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
optimizer.step()

Los gradientes se acumulan por defecto. Si no se limpian antes del siguiente backward pass, se suman a los anteriores. zero_grad(set_to_none=True) deja los gradientes en None hasta que se calculen y puede reducir escrituras de memoria frente a rellenarlos con ceros.

La actualización de gradiente más sencilla es:

θ(t+1) = θ(t) - η · ∇θ L

η es el learning rate: determina el tamaño del paso. Un gradiente indica una dirección local de incremento del objetivo; el signo negativo mueve los parámetros en la dirección que, localmente, reduce la loss. En redes profundas, sin embargo, la escala de gradientes varía entre parámetros y pasos. Por eso se usan optimizadores adaptativos y políticas de learning rate.

7. AdamW: momentos adaptativos y weight decay desacoplado

Adam mantiene estimaciones exponenciales del primer y segundo momento del gradiente. En forma simplificada:

m(t) = β1 · m(t-1) + (1 - β1) · g(t)
v(t) = β2 · v(t-1) + (1 - β2) · g(t)^2
m_hat = m(t) / (1 - β1^t)
v_hat = v(t) / (1 - β2^t)
θ ← θ - η · m_hat / (sqrt(v_hat) + ε)

El primer momento suaviza la dirección del gradiente; el segundo estima su escala por coordenada. Las correcciones de bias compensan que ambas estimaciones comienzan en cero. Cada parámetro obtiene una escala de actualización adaptada a su historial, aunque esto no elimina la necesidad de elegir bien el learning rate global.

AdamW separa el weight decay de la actualización basada en el gradiente. De forma intuitiva, combina el paso adaptativo de Adam con una contracción multiplicativa de los parámetros sujetos a decay:

θ ← θ - η · update_adam - η · λ · θ

La separación importa. Los autores de Decoupled Weight Decay Regularization muestran que, con optimizadores adaptativos como Adam, añadir una penalización L2 al objetivo no es equivalente a aplicar weight decay desacoplado. PyTorch implementa AdamW con el decay separado del cálculo de los momentos.

En entrenamiento real no siempre se aplica decay a todos los tensores. Es común crear grupos para que las matrices de pesos reciban weight decay y que bias y parámetros de LayerNorm no lo reciban. Es una decisión de configuración, no una propiedad automática de toda implementación. El laboratorio aplica decay a matrices lineales y lo excluye de embeddings, bias y parámetros unidimensionales.

Una prueba escalar aísla el concepto: con parámetro inicial 1, gradiente cero, learning rate 0,1 y weight decay 0,2, AdamW deja el parámetro en 0,98. No hay señal de la loss que empuje el peso; el cambio procede del término desacoplado de decay.

8. Learning-rate schedules: controlar el tamaño del paso

Un learning rate constante es una referencia sencilla, pero muchos entrenamientos usan una política que cambia η durante el proceso. Dos fases habituales son:

  • Warmup: comienza con una tasa pequeña y la incrementa gradualmente durante un número definido de updates.
  • Decay: después de alcanzar el pico, reduce la tasa para que las actualizaciones sean progresivamente más pequeñas.

En cosine decay, la transición desde ηmax hasta ηmin sigue media onda de coseno:

η(t) = ηmin + 0.5 · (ηmax - ηmin) · (1 + cos(π · progress))

progress recorre de 0 a 1 durante la fase de decay. Un warmup lineal anterior puede escribirse así:

η(t) = ηmax · (t + 1) / warmup_steps

El paper original del Transformer popularizó una política con warmup e inverse-square-root decay; cosine decay es otra familia de schedule, no una reproducción exacta de aquella receta. PyTorch ofrece implementaciones como LinearLR, CosineAnnealingLR y SequentialLR. En una rutina por update, el scheduler suele avanzar después de optimizer.step(), siguiendo el contrato de la API concreta.

No hay un schedule que sea mejor para cualquier entrenamiento. Presupuesto total de tokens, arquitectura, tamaño de batch, inicialización, optimizador y dataset afectan a la política que funciona. Una comparación justa debe mantener constantes el resto de condiciones.

9. Gradient clipping y estabilidad del update

El global norm clipping calcula la norma conjunta de los gradientes. Si supera un umbral c, multiplica todos por el mismo factor para que la norma final no exceda c:

scale = min(1, c / (||g||2 + ε))
g ← scale · g

Esto limita el tamaño del vector de gradiente antes de que el optimizador lo utilice. No cambia la dirección relativa entre gradientes de parámetros, aunque sí reduce su magnitud. En PyTorch, clip_grad_norm_ modifica los gradientes in-place y devuelve la norma total previa al clipping.

Clipping no arregla una máscara incorrecta, un target mal alineado, una loss no finita, un learning rate inadecuado ni un problema de datos. Es una salvaguarda frente a normas excesivas; conviene registrar la norma previa para saber con qué frecuencia se activa.

10. Train loss, validation loss y generalización

La training loss mide el objetivo sobre ejemplos que participan en la actualización de parámetros. La validation loss mide el mismo objetivo sobre ejemplos reservados que no intervienen en el backward pass. La segunda sirve para vigilar si el modelo mejora fuera de los datos que está optimizando directamente.

Una training loss que cae mientras la validation loss deja de mejorar o empieza a subir puede ser señal de overfitting. Una brecha pequeña no prueba generalización robusta: depende del tamaño y diversidad del conjunto, de la partición, del tokenizer y de si los ejemplos son realmente independientes. Una split aleatoria por ventanas sobre un documento puede producir solapamiento de contexto; para una evaluación seria hay que separar por documentos o por una frontera temporal/dominio adecuada.

También hay una diferencia entre pretraining y fine-tuning. El primero suele optimizar el objetivo autoregresivo sobre corpus amplios y variados. El segundo adapta un modelo ya entrenado a una distribución u objetivo más específico, normalmente con otro dataset y otro presupuesto. La loss de fine-tuning no se compara directamente con la de pretraining si cambian los datos, tokenizer o cálculo.

La loss responde a una pregunta acotada: ¿qué probabilidad asigna el modelo a los siguientes tokens reales de este conjunto? No mide por sí sola factualidad, razonamiento, seguridad, utilidad ni comportamiento en despliegue.

La comparación utiliza dos ejecuciones con los mismos pesos iniciales, la misma secuencia precomputada de minibatches y la misma configuración del optimizador. Solo cambia la política de learning rate:

  • Constant: 5e-4 en los 240 updates.
  • Warmup + cosine: warmup lineal durante 24 updates; después descenso cosenoidal desde 5e-4 hasta 5e-5.

La evaluación usa ventanas fijas: ocho minibatches de entrenamiento y ocho de validación. La validación no se utiliza en ningún backward pass. Para que la codificación character-level pueda representar todos los caracteres del corpus, el alfabeto se construye con ambos splits; esto revela el inventario de caracteres de validation, pero no aporta sus ejemplos a los gradientes. En esta ejecución, AdamW con tasa constante termina con validation loss 2,4630, mientras que warmup + cosine termina en 2,6363. No es una prueba de superioridad general de la tasa constante. El schedule pasa una fracción del presupuesto por debajo de la tasa máxima; con más updates, otro dataset o una arquitectura mayor, la relación puede cambiar. El resultado muestra por qué conviene medir el schedule elegido en vez de asumir que un patrón conocido siempre mejora el resultado.

La brecha final entre train y validation es 0,0762 para la política constante y 0,0461 para warmup + cosine. En este experimento no aparece una brecha grande; con una única semilla, una muestra pequeña y un corpus estrecho no debemos convertir esa observación en una conclusión fuerte sobre generalización.

13. Errores frecuentes al entrenar

  • Targets sin desplazar: el modelo aprende a reproducir el token que ya ve en vez de predecir el siguiente.
  • Softmax antes de Cross Entropy: se entrega una distribución normalizada donde la función espera logits.
  • Gradientes acumulados: se omite zero_grad y los updates mezclan accidentalmente minibatches anteriores.
  • Scheduler desfasado: se llama step en el orden equivocado o se cuentan epochs cuando la configuración está definida por updates.
  • Validación dentro del entrenamiento: se calculan gradientes sobre validation o se ajustan hiperparámetros continuamente a un conjunto que luego se presenta como test independiente.
  • Interpretar solo train loss: una pérdida de entrenamiento que baja puede coexistir con peor rendimiento fuera del corpus de ajuste.
  • Copiar hiperparámetros sin contexto: valores de un paper no son presets universales; importan batch global, tokens por update, arquitectura, precision y presupuesto total.

14. Qué no demuestra el laboratorio

El modelo tiene 62.880 parámetros y trabaja a nivel de carácter con un corpus técnico breve. No es una réplica de GPT-2, GPT-3 ni de un LLM actual. No mide calidad conversacional, capacidades emergentes, razonamiento, factualidad, seguridad, throughput de GPU, uso de memoria acelerada ni escalabilidad distribuida.

La comparación usa una única semilla, 240 updates por política y una muestra fija de evaluación. Para evaluar robustez habría que repetir con varias semillas, varios datasets y más presupuesto, documentar incertidumbre y controlar decisiones adicionales de optimización. Tampoco puede aislarse el efecto de un schedule en un modelo grande a partir de este microexperimento.

Qué sí podemos afirmar

El objetivo next-token está alineado y comprobado; la derivada de Cross Entropy coincide con autograd; AdamW aplica weight decay desacoplado; clipping limita la norma; y, en esta comparación concreta, ambas políticas reducen la pérdida, con una ventaja de la tasa constante al final de los 240 updates. Eso es lo que miden las evidencias, ni más ni menos.

15. Qué viene después

Ya sabemos cómo aprende el modelo: el objetivo define qué token debe predecir, Cross Entropy convierte logits en una señal, backpropagation distribuye gradientes y AdamW transforma esa señal en actualizaciones. El siguiente capítulo cambia de fase: una vez entrenado el modelo, ¿qué ocurre cuando recibe una petición y tiene que generar tokens?

El capítulo 04 estudiará LLM Inference: Prefill, Decode y KV Cache. Separaremos el procesamiento del prompt de la generación autoregresiva, seguiremos los tensores que se reutilizan y veremos por qué la memoria y el ancho de banda importan tanto como los FLOPs.
