Self-Attention Deep Dive: mathematics, gradients and modern variants

Query, Key and Value are not decorative names. They are learned projections that form a differentiable operation: compute compatibilities, normalise them, and mix information. We derive the operation, follow its backward pass and measure what changes when dimensions or Key/Value sharing are modified.

The central question

How does a sequence of vectors become a new contextual representation, and how does the optimiser know what to change? The lab implements the forward pass, derives Q/K/V gradients manually, compares them with autograd, checks one derivative using finite differences, and studies attention variants that affect inference memory.

1. The mechanism we isolate

In the previous chapter we built the anatomy of a decoder-only Transformer and followed the path from token IDs to logits. Here we zoom in on the component that mixes information across positions: self-attention. We will not train another language model. We will isolate the operation and test its properties with controlled tensors.

In self-attention, Query, Key and Value are calculated from the same sequence of hidden states. A Query is compared with the available Keys; the result determines how much each Value contributes to the output. This is a functional description, not a literal semantic interpretation: a Query is not necessarily a linguistic question, nor is a Key an interpretable label. They are learned vectors in a representation space.

The original Vaswani et al. (2017) formulation is scaled dot-product attention. Modern Transformers add architectural and implementation choices —causality, RoPE, GQA, efficient kernels— that should be separated so we do not mix three different questions: what attention computes, how it encodes position, and how it is executed with less memory traffic.

2. From X to Q, K and V: learned projections

We start from an input that already contains vector representations. For a batch with sequence length T and model dimension d_model:

X: [B, T, d_model]

The block applies three independent linear projections:

Q = X @ W_Q + b_Q
K = X @ W_K + b_K
V = X @ W_V + b_V

In conventional Multi-Head Attention, each projection produces H × d_head features per position. With d_model = 512, H = 8 and d_head = 64, the projected tensor can be reshaped as follows:

Q, K, V: [B, T, 512]
reshape: [B, T, 8, 64]
transpose: [B, 8, T, 64]

The last shape explicitly separates the head dimension. Each head now performs attention in parallel. This does not mean there are eight independent models: all heads receive the same input, their projection matrices are jointly trained, and their outputs are combined again.

What each projection contributes

  • Query (Q): the vector used to score compatibility between a position and the available Keys.
  • Key (K): the vector against which each Query is compared to calculate scores.
  • Value (V): the vector content combined using the resulting weights.

The important distinction is that Key, together with Query, determines how much a position weighs; Value provides the aggregated content. Changing K can alter which positions are attended to without directly changing the content stored in V. Changing V can modify the output even when attention weights remain identical.

3. Scores: why divide by the square root of d_head?

For each Query we calculate the dot product against all Keys. With Q shaped [B, H, T, d_head] and K shaped the same way:

S = Q @ K.transpose(-2, -1)
S.shape = [B, H, T, T]
S_scaled = S / sqrt(d_head)

The dot product measures alignment in the learned space. Its scale, however, depends on the dimension. If Q and K components were independent, zero-mean, unit-variance variables, the dot product would be a sum of d_head products and its variance would grow approximately in proportion to d_head. As the dimension increases, logits entering softmax would tend to have larger magnitudes.

The 1 / sqrt(d_head) factor normalises that scale under this reference assumption. It does not guarantee that every trained score has unit variance or remove all conditioning issues, but it prevents dimension alone from systematically pushing logits towards extreme values. The original paper connects large dot products with softmax regions that have very small gradients.

Experiment: scaling changes the distribution

We generate 512 Query vectors and 24 Keys per Query, all with standard-normal components. We repeat the calculation for d_head = 8, 16, 32, 64, 128 and 256. We compare the same dot product with and without division by sqrt(d_head). We measure mean softmax entropy, in nats, and mean maximum weight.

4. Softmax: from compatibilities to weights

After the dot product, softmax is applied along the Key axis. For position i, the attention weight assigned to position j is:

P[i,j] = exp(S[i,j]) / sum_k exp(S[i,k])

Each row is normalised separately. The whole matrix is not normalised at once: each Query has its own distribution over the positions it can consult. Values are non-negative and comparable within that row.

In code, the axis matters: for scores shaped [B, H, T_query, T_key], the usual call is softmax(scores, dim=-1). Applying softmax along the Query axis would produce a different operation, not a harmless variation.

During training, dropout may be applied to attention weights after softmax. At inference, dropout_p is normally zero. PyTorch notes that its scaled_dot_product_attention API applies the requested dropout even when called from a module in evaluation mode: the caller must explicitly pass zero at evaluation time.

5. Causal masking and padding: constraints before normalisation

An autoregressive decoder cannot consult future tokens. When position i computes its representation, it may only use positions j ≤ i. A causal mask assigns negative infinity to forbidden scores before softmax:

scores[i, j] = -inf  when j > i
weights = softmax(scores, dim=-1)

Since exp(−infinity) = 0, future positions receive exactly zero weight. A causal mask does not hide the past: it preserves the entire prefix, including the current position.

A padding mask solves a different problem: it prevents attention to padding positions added to make sequences in a batch the same length. In a decoder with padding, both restrictions can be combined if the broadcastable mask is constructed correctly. Do not conflate them: causality expresses generation order; padding expresses which input positions do not contain real data.

PyTorch mask semantics

In torch.nn.functional.scaled_dot_product_attention, a Boolean mask value of True means the position is allowed to participate. In MultiheadAttention, key_padding_mask uses True to indicate positions to mask out. When moving between these APIs, invert the mask when required. Always check the documentation for the exact function you call.

6. Weighted sum and output projection

The attention matrix P is applied to V:

O = P @ V
O.shape = [B, H, T, d_head]

For each Query, the output is a weighted combination of the Values allowed by the mask. The operation does not simply select the position with the largest weight; every position with non-zero weight contributes to the sum. This mixture is differentiable with respect to P and V.

In Multi-Head Attention, the H head outputs are concatenated and passed through another learned projection:

O_concat = concat(O_1, ..., O_H)
Y = O_concat @ W_O

If d_head = d_model / H, concatenation returns d_model features. W_O allows the next layer to mix information from different sub-representations. The output is usually incorporated into the residual stream of the Transformer block, but that residual connection belongs to the full block, not to the isolated attention operation.

7. Backpropagation: following the reverse path

So far we have described the forward pass. During training, a downstream loss produces a gradient on output O. Reverse-mode automatic differentiation then applies the chain rule through P, S, Q, K and V, and finally through the W_Q, W_K and W_V matrices.

For algebraic clarity, derive attention without a mask; with a causal mask, forbidden score positions have zero gradient. Define:

S = (Q @ K.T) / sqrt(d_head)
P = softmax(S)
O = P @ V

Let G = dL/dO be the gradient arriving from the next operation. For the multiplication O = P V, the matrix derivatives are:

dL/dV = P.T @ G
dL/dP = G @ V.T

This separates two paths. The gradient on V changes the content being mixed. The gradient on P changes how much each position weighs, and must travel backwards through softmax and the QK.T product. Thus both Query and Key receive gradients through the score path.

8. The softmax gradient: why the distribution matters

For one row p = softmax(s), the softmax Jacobian is:

J = diag(p) - p @ p.T

Applying it to the incoming gradient vector is equivalent to:

dL/ds_j = p_j * (dL/dp_j - sum_k(p_k * dL/dp_k))

The expression shows that positions compete within the same row. A score gradient depends on the gradient received by its weight and on the distribution-weighted mean. When softmax is almost entirely concentrated on one position, many probabilities approach zero and their local derivatives can become small. This is one reason why logit scaling is not merely cosmetic.

In the actual mechanism, scores are also the result of QK.T / sqrt(d_head). Applying the chain rule gives:

dL/dQ = (dL/dS @ K) / sqrt(d_head)
dL/dK = (dL/dS).T @ Q / sqrt(d_head)

The division by sqrt(d_head) appears in the backward pass too, because it is part of the forward pass. It does not disappear when differentiating. Removing or changing the scale alters both the attention distribution and the gradient magnitude returning to Q and K.

9. Gradients of the projection matrices

Q, K and V are not isolated parameters: they are obtained by projecting X. For a linear multiplication Q = X W_Q, the gradient of W_Q combines the input X with the gradient reaching Q. With batched tensors, contributions from batches and positions are summed; conceptually:

dL/dW_Q = X.T @ (dL/dQ)
dL/dW_K = X.T @ (dL/dK)
dL/dW_V = X.T @ (dL/dV)

If biases are present, their gradients sum the corresponding contributions. The same X feeds all three projections, so the total gradient on X accumulates the paths through Q, K and V. This is why Query, Key and Value should not be described as three independent channels: they share the same origin and are optimised in the context of the same loss.

In the lab we use float64 so that numerical errors in the gradient check remain very small. We manually derive dQ, dK and dV for a squared-error loss, compare them tensor by tensor with torch.autograd.grad, and independently validate one element of W_Q using central finite differences:

gradient_fd ≈ (loss(W_Q + ε) - loss(W_Q - ε)) / (2 ε)

Finite differences do not replace autograd: the result depends on epsilon and rounding. They provide an independent check on the derivative implementation, not a training method.

10. What changes when the number of heads changes?

In the usual configuration, total attention width is kept fixed: H × d_head = d_model. If d_model = 512:

With fused projections from d_model to d_model, the Q/K/V/O parameter count remains constant as H changes, provided total width remains fixed. What changes is how that width is partitioned: more heads mean narrower subspaces; fewer heads mean wider subspaces. There is no simple rule that adding heads always improves a model. Training, data, architecture and compute budget also matter.

This reasoning is no longer identical when we reduce the number of Key/Value heads: we are not just rearranging the same width, but sharing K/V projections between multiple Query heads.

11. MHA, MQA and GQA: sharing Keys and Values

Traditional Multi-Head Attention assigns each Query head its own Key and Value head. Multi-Query Attention (MQA) keeps multiple Query heads but shares a single K and V head. Grouped-Query Attention (GQA) provides a middle ground: each group of Query heads shares one K/V pair.

If H_q is the number of Query heads and H_kv is the number of Key/Value heads, each group contains H_q / H_kv Query heads. H_q is typically divisible by H_kv for a uniform grouping. H_kv = H_q gives MHA; H_kv = 1 gives MQA; intermediate values represent GQA.

The motivation in autoregressive inference is the size of the KV cache. Each processed token contributes K and V tensors that can be reused while generating later tokens. Storing fewer K/V heads reduces the state that must be retained and read at each step. The paper by Ainslie et al. (2023) studies GQA as a compromise between MHA quality and MQA efficiency. Sharing K/V is not free: it changes the parameterisation, and the model must learn with that structure or be adapted to it.

12. The KV-cache impact: a scalable calculation

Memory required to store Keys and Values per layer, per sequence and per token can be estimated as:

KV bytes = 2 × H_kv × d_head × bytes_per_element
Cache bytes = KV bytes × sequence_length × batch_size × layers

The first factor 2 represents Key and Value. To illustrate the effect, use 32 Query heads, d_head = 128, BF16 (2 bytes) and a 4,096-token sequence. The table shows one layer and one sequence; multiply by batch and layer count to estimate the model total:

DesignKV headsBytes per token and layerKV cache per layer
MHA3216 KiB64 MiB
GQA84 KiB16 MiB
GQA42 KiB8 MiB
MQA1512 B2 MiB

In this example, GQA with four KV heads reduces theoretical cache to 12.5% of MHA; MQA brings it down to 3.125%. The reduction is proportional to the number of KV heads while d_head, sequence length, batch and dtype remain constant. This is not a measurement of allocator behaviour, paged layout, fragmentation or kernel temporary memory.

This is where attention design meets serving: during decode, each new token must consult the accumulated Keys and Values. With long generations or high concurrency, KV-cache size and reads become first-order architecture decisions. We will study this at the Prefill/Decode level in the inference chapter and at the block-management level with vLLM.

13. RoPE: relative position through rotations

Q, K and V alone do not indicate token order. A positional mechanism must inject that information. In chapter one we saw learned positional embeddings as a teaching option; many modern LLMs use Rotary Position Embedding (RoPE).

RoPE divides the dimensions of each Q and K vector into pairs and rotates each pair by an angle that depends on position. Different pairs use different frequencies. In compact notation:

q_m = R_m q
k_n = R_n k
(R_m q) · (R_n k) = q · (R_(n-m) k)

The useful property is that the dot product between Query at position m and Key at position n incorporates a dependency on the relative difference n − m. RoPE rotates Q and K, not V. The RoFormer paper (Su et al., 2021) develops this construction and its properties.

The lab test numerically verifies this rotation identity on random float64 vectors. It does not measure extrapolation to longer contexts, compare perplexity or prove that every RoPE configuration works well beyond its training range. Real systems add further decisions: frequency base, position scaling and context-extension methods.

14. PyTorch reference implementation

The following version shows the forward-pass core for tensors shaped [B, H, T, d_head]. It is written to make the operation visible, not to compete with fused kernels:

import math
import torch

def self_attention(q, k, v, causal=True):
    scores = (q @ k.transpose(-2, -1)) / math.sqrt(q.size(-1))

    if causal:
        t_q, t_k = scores.shape[-2:]
        mask = torch.triu(
            torch.ones(t_q, t_k, dtype=torch.bool, device=q.device),
            diagonal=1
        )
        scores = scores.masked_fill(mask, float("-inf"))

    weights = torch.softmax(scores, dim=-1)
    output = weights @ v
    return output, weights

PyTorch exposes the optimised API through torch.nn.functional.scaled_dot_product_attention. On CUDA it can select specialised implementations such as FlashAttention-2, Memory-Efficient Attention or PyTorch's math kernel, depending on backend and tensor constraints. CPU uses a compatible PyTorch implementation; this lab therefore does not present GPU timings or claim to measure FlashAttention.

GQA needs an additional warning: PyTorch 2.14 documentation marks enable_gqa as experimental and documents support on selected CUDA kernels. In this CPU lab we explicitly expand each shared K/V head to the Query heads in its group and compare the result with standard SDPA. We do not label this a benchmark of the native GQA kernel.

FlashAttention solves another dimension of the problem: it is an exact, IO-aware algorithm that uses tiling to reduce reads and writes between HBM and on-chip memory. It does not change the mathematical definition of attention derived here; it changes how the calculation is executed and which intermediate tensors are materialised. Kernel design, memory bandwidth and benchmarking deserve their own investigation.

17. What these results do not prove

The tests are designed to isolate algebraic properties, not infer LLM quality. Random Q/K vectors do not necessarily reproduce the distributions of a trained model. The softmax experiment uses a fixed seed; its values are one reproducible example, not a statistical law for every network.

Parameter and KV-cache calculations are analytical estimates with declared dimensions. We did not measure actual GPU memory allocation, fragmentation, throughput, TTFT or TPOT. The CPU GQA test expands the shared KV heads; it does not run or measure the native CUDA kernel. The RoPE test validates a mathematical identity, not generation quality or context extrapolation.

Finally, an attention map is not automatically a faithful explanation of a prediction. Jain and Wallace (2019) showed important limitations in treating weights as explanations; Wiegreffe and Pinter (2019) discussed how conclusions depend on the definition of explanation and evaluation method. The cautious position is to use weights as internal signals that may guide an investigation, never as standalone proof of causality or interpretability.

The distinction to remember

Attention describes how information is mixed within one layer. On its own, it does not describe all processing in a Transformer, including residual streams, MLPs, normalisation, later layers or the complete decision process.

18. What comes next

Chapter 03 will take the next step: how a model is trained so that these projections and its other parameters learn to predict the next token. We will derive Cross Entropy, backpropagation through the full network, AdamW, learning-rate schedules, and the difference between reducing a loss and demonstrating generalisation.

Before moving on, keep the mechanism clear: Q and K produce compatibilities; scaling conditions the logits; softmax produces weights; V provides content; the output aggregates and projects; autograd distributes gradients along each path. MHA, GQA and MQA change how K/V projections are shared, while RoPE incorporates position through rotations.
