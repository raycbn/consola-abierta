Inside a Transformer: from tokens to a decoder-only LLM

An LLM is not a magical black box or merely a chain of prompts. It is a neural network built from tensors, projections, matrix products, normalisation, residual paths and a very specific statistical objective. We will trace its internal dataflow and reproduce a small version from scratch with PyTorch.

What you will see

A decoder-only Transformer implemented with PyTorch without relying on nn.Transformer. We train a tiny 110,464-parameter model on a CPU, inspect its tensors and verify four properties: output shapes, attention normalisation, no access to future tokens, and numerical equivalence with PyTorch's official scaled_dot_product_attention API.

1. What a Transformer is — and is not

A Transformer is a neural-network architecture based on attention mechanisms and feed-forward layers. The paper that introduced it, Attention Is All You Need, replaced recurrence in dominant sequence models with attention operations that can relate sequence positions in parallel during training. The original design was encoder-decoder and was initially evaluated on machine translation; it was not introduced as a chatbot or as a decoder-only GPT. Vaswani et al., 2017.

A Large Language Model (LLM) is a high-capacity language model trained on large amounts of data, usually with a token-prediction objective and subsequent adaptation stages. Many current LLMs use a Transformer decoder-only architecture, but the terms are not interchangeable: Transformer describes an architecture family; LLM describes the model's scale, training and task. Language models can be encoder-only, encoder-decoder, or use architectures that combine other mechanisms.

The path we will follow is:

  1. Text is converted into token IDs.
  2. An embedding table maps IDs to dense vectors and positional information is added.
  3. Transformer blocks mix context through self-attention and transform each position with a feed-forward network.
  4. A final projection produces logits over the vocabulary.
  5. The loss compares logits with the next token, and backpropagation updates the weights.

2. Encoder, decoder and encoder-decoder are not interchangeable

It is important to distinguish three architectural patterns because they determine attention direction and the training objective.

FamilyTypical attentionCommon use
Encoder-onlyBidirectional within the inputContextual representations, classification and understanding. BERT is the classic example.
Decoder-onlyCausal: each position sees its prefixAutoregressive language modelling and text generation. GPT is the classic example.
Encoder-decoderBidirectional encoder, causal decoder and cross-attentionSequence-to-sequence transformation, such as translation and some seq2seq tasks.

In self-attention, Query, Key and Value come from the same sequence of hidden states. In cross-attention, Query comes from one sequence (for example, the decoder) while Key/Value come from another (the encoder memory). A decoder-only GPT does not need cross-attention because it has no separate encoder to query.

Therefore, when we draw a modern LLM as a repeated stack of decoder blocks, we are not literally reproducing the entire 2017 paper diagram. We are describing a later family popularised by GPT. The original paper remains the primary reference for scaled dot-product attention, multi-head attention, positional encoding and the encoder-decoder Transformer.

3. From text to embeddings: the first tensor shapes

A neural network does not receive words as strings. A tokenizer splits the input into units — tokens — and assigns an integer ID to each one. A token may represent a word, part of a word, punctuation, bytes or characters, depending on the algorithm and vocabulary.

Subword tokenisation is common in production, including variants of Byte Pair Encoding (BPE) and related methods. It avoids relying on a vocabulary of complete words and can represent unseen terms by combining smaller units. Tokenisation affects token count, effective context, code handling and language coverage. Our lab uses individual characters: it is deliberately simple and does not represent the tokenizer of GPT, Llama or other commercial models.

Assume a batch of B sequences with length T and vocabulary size V. After tokenisation we have an ID tensor:

input_ids.shape = (B, T)
input_ids.dtype = torch.int64

An nn.Embedding(V, d_model) layer behaves as a trainable lookup table. Each ID selects a row, producing a vector of dimension d_model:

token_embeddings = token_embedding(input_ids)
# (B, T) -> (B, T, d_model)

The word embedding can suggest that each vector contains a human-written semantic definition. It does not. These are parameters learned by optimisation; their geometry emerges from the data, objective, architecture and training process.

In our TinyGPT, the vocabulary contains 66 characters and d_model=64. An embedding tensor for a batch of 16 sequences with 96 positions therefore has shape (16, 96, 64). In a real LLM, V is usually much larger, as is the embedding dimension.

4. Self-attention: what Query, Key and Value compute

The intuition behind attention is that a position builds a representation by combining information from other positions. Each hidden vector X is projected into three learned spaces:

Q = X W_Q, K = X W_K and V = X W_V.

Query (Q) represents the pattern a position uses to look for information; Key (K) represents what each position can be matched against; Value (V) contains the vector that will be mixed after attention weights are calculated. These are conceptual guides, not literal statements about what a head “thinks”. The matrices W_Q, W_K and W_V are learned parameters.

4.1 Scaled dot-product attention

First, each Query is compared with each Key using a matrix product. The result is scaled by the square root of the head dimension, normalised with softmax, and applied to Values:

Attention(Q, K, V) = softmax((Q · Kᵀ) / √dₖ) · V

With per-head tensors, typical shapes are:

TensorShapeMeaning
Q(B, h, T, d_h)Queries for each head
K(B, h, T, d_h)Keys for each head
V(B, h, T, d_h)Values for each head
Q @ Kᵀ(B, h, T, T)Score for each query-key pair
Softmax(scores)(B, h, T, T)Row-normalised weights
Weights @ V(B, h, T, d_h)Aggregated context per head

Why divide by √d_k? Under the simplifying assumption that Q and K components are independent, zero-mean and unit-variance, the variance of their dot product grows with d_k. As its magnitude increases, softmax logits can enter saturated regions where gradients become small. Scaling stabilises score magnitudes before softmax. This is an important numerical design choice, not decorative notation.

4.2 What softmax does

For each query position, softmax turns scores into a distribution of weights that sum to one. In simplified form, softmax(sᵢ)=exp(sᵢ)/Σⱼ exp(sⱼ). A weight determines how much each Value contributes to the output. If a causal mask is applied, disallowed future positions are replaced by −∞ before softmax and receive zero probability.

Our lab implements these operations explicitly with matrix products, masked_fill and F.softmax. This is done to inspect scores and weights, not because it is always the fastest implementation.

5. Multi-Head Attention: multiple subspaces in parallel

A single head performs aggregation in one subspace. Multi-Head Attention projects Q, K and V into several learned subspaces, computes attention in parallel and concatenates the results. The output is projected back to d_model:

\[\operatorname{MultiHead}(Q,K,V)=\operatorname{Concat}(head_1,\ldots,head_h)W_O\]

In a common configuration, d_h = d_model / h. Our model uses d_model=64 and four heads, so each head operates on 16 dimensions. The division must be exact in this implementation.

One head may assign weight to different positions from another, but we should not label a head as “the verb head” or “the memory head” without specific analysis. Attention weights describe one operation; by themselves they do not provide a complete explanation of model behaviour.

6. Causal masking: preventing the model from seeing the future

An autoregressive decoder must predict the next token using only the available prefix. Position t may query positions s ≤ t, but not later positions. The causal mask has a lower-triangular structure:

In the manual implementation, a boolean mask determines which pairs are legal. Scores for future positions are replaced with −∞ before softmax. Attention therefore cannot transfer future information into the past.

scores = (q @ k.transpose(-2, -1)) / math.sqrt(head_dim)
scores = scores.masked_fill(~causal_mask, float("-inf"))
weights = torch.softmax(scores, dim=-1)
out = weights @ v

The mask must not be applied after softmax: doing so would let future positions take part in normalisation and change the weights of permitted positions.

6.1 Teacher forcing and shifted targets

During training the complete sequence is available, so predictions for many positions can be calculated in parallel. Inputs and targets are shifted by one position: the model receives tokens x[0:T] and the target is x[1:T+1]. The decoder uses its causal mask so each position only sees its prefix. Providing the correct previous tokens while computing the loss is commonly called teacher forcing.

The mask prevents information leakage, but inputs and targets must also be aligned correctly. A correct mask with incorrectly shifted targets still makes the experiment invalid.

7. How does it know the order? Positional information

Self-attention without positional information does not encode the original position of each token by itself. If input elements are permuted, attention relations are permuted in a compatible way. The model needs an additional signal to distinguish “A before B” from “B before A”.

The original Transformer added sinusoidal encodings with different frequencies to the embeddings. For position pos and dimension i:

PE(pos, 2i)     = sin(pos / 10000^(2i / d_model))
PE(pos, 2i + 1) = cos(pos / 10000^(2i / d_model))

GPT-2 uses learned positional embeddings: a trainable table indexed by position. Other architectures introduce relative mechanisms or Rotary Position Embeddings (RoPE), which rotate Query and Key representations to encode positional relations in attention scores. RoPE deserves its own investigation and will be covered in a later article on modern attention.

Our experiment uses a learned position table bounded by block_size=96. It therefore does not demonstrate extrapolation to longer contexts and does not implement RoPE.

8. Anatomy of a decoder block

A decoder-only block combines two main sub-blocks: causal self-attention and a feed-forward network. Both are wrapped by residual paths and normalisation. The lab uses a Pre-LayerNorm variant:

x = x + Attention(LayerNorm(x))
x = x + FeedForward(LayerNorm(x))

8.1 Residual connections

A residual connection adds the input of a sub-block to its transformation: x ← x + F(x). It preserves an identity path and helps gradient flow through deep networks. The article diagram simplifies these branches; in the code they are explicit operations.

8.2 Layer Normalization: Pre-LN vs. Post-LN

The original Transformer used LayerNorm(x + Sublayer(x)), a Post-LN arrangement. GPT-2 moved normalisation to the input of each sub-block and added a final normalisation, establishing a Pre-LN variant. These details are not interchangeable: they change gradient paths and optimisation dynamics. TinyGPT follows Pre-LN to approximate the GPT family we are studying.

8.3 Feed-Forward Network

After attention, each position passes through the same feed-forward network. A common form projects d_model → 4·d_model, applies a non-linear GELU activation and projects back 4·d_model → d_model. The same network is applied to every position. Attention mixes information between positions; the MLP transforms the channels at each position. They perform different roles.

The lab uses two decoder blocks. Production models often have many more layers and use other activation, normalisation, gating and dimension choices.

9. From hidden states to logits

After the final layer and normalisation, each position has a contextual representation of size d_model. A linear projection to vocabulary size produces logits: unnormalised scores for every possible token.

logits = lm_head(hidden_states)
# (B, T, d_model) -> (B, T, vocab_size)

To compute the loss, we flatten the batch and time dimensions and compare each logit vector with the target ID. CrossEntropyLoss internally combines LogSoftmax and Negative Log Likelihood in a numerically stable way. We should not apply softmax before using this function.

The next-token objective can be written as the autoregressive factorisation:

p(x₁, …, x_T) = ∏(t = 1…T) p(xₜ | x₁, …, xₜ₋₁)

In log space, maximising sequence probability is equivalent to minimising the sum of next-token losses. Loss measures statistical prediction quality on examples; it is not a direct measure of understanding, truthfulness or generated-text usefulness.

10. Training and inference execute different workloads

10.1 Training: many positions in parallel

During training, the sequence tokens are already available. The causal mask allows predictions for all positions to be computed in one forward pass while preserving the rule that each position only sees its past. The loss is computed, backward() runs and the optimiser updates parameters.

optimizer.zero_grad(set_to_none=True)
logits, loss = model(input_ids, targets)
loss.backward()
optimizer.step()

Our lab uses AdamW and gradient clipping to norm 1.0. The CSV records loss and pre-clipping gradient norm for every step. The curve separates training loss from validation loss; the validation split is kept out of optimiser updates.

10.2 Inference: autoregressive generation

During generation, the model does not know future tokens. It computes a distribution for the next token, selects one according to a sampling strategy, appends it to the context and repeats. This sequential dependency is one reason LLM serving requires dedicated optimisations.

The TinyGPT generator recomputes the full context at each step. It does not implement a KV Cache; it must not be used to benchmark serving performance. Key/value caching, prefill/decode, batching and engines such as vLLM are covered in later articles.

11. Computational cost: why context length matters

For one attention head, the product QKᵀ produces a T × T score matrix. Its size grows quadratically with sequence length: doubling T quadruples the number of query-key pairs. This matrix can be a significant memory and compute cost.

This does not mean the entire Transformer has only O(T²) cost. Projections and the MLP also depend on sequence length, hidden dimension, batch size, layer count and head count. In a standard dense model, projection/MLP work grows with sequence length and hidden-dimension terms; attention adds a quadratic-in-sequence-length term. Which part dominates depends on dimensions and hardware.

Optimised implementations can avoid materialising the full attention matrix or use fused kernels. PyTorch exposes torch.nn.functional.scaled_dot_product_attention, which selects a compatible implementation based on device, dtype, shape and settings. CUDA may enable specialised kernels such as FlashAttention; our host only runs the CPU backend, so this lab does not measure GPU performance.

14. Limits and interpretation pitfalls

  • We did not train a general-purpose LLM. The model has 110,464 parameters, many orders of magnitude below current large models. Its purpose is to study architecture.
  • The tokenizer is character-level. It does not represent modern BPE, byte-level BPE or subword tokenisation. Sequence length and cost are not comparable.
  • The corpus is small and domain-specific. Metrics depend on its distribution, random seed and split. They cannot be extrapolated to external benchmarks.
  • We did not measure serving performance. The script does not implement KV Cache, batching, quantisation or GPU kernels. Do not publish tokens/s or throughput comparisons from this run.
  • The heatmap does not explain the model by itself. Attention weights describe a particular operation; behaviour emerges from projections, multiple layers, MLPs, normalisation and residual paths.
  • Loss does not measure truthfulness. Lower loss does not guarantee correct answers, reliable reasoning or absence of hallucinations.
