How an LLM Learns: Next-Token Prediction, Cross Entropy, Backpropagation and AdamW

A Transformer does not learn because someone explains what a text means. It learns by adjusting its parameters to increase the probability of the next observed token. We follow that process from input/target alignment to weight updates, then measure what changes when the learning-rate schedule changes.

The central question

We have a token sequence and a model that returns logits at each position. How do we turn that output into a learning signal, propagate it to every parameter, and decide how far each parameter should move? We will separate the statistical objective, gradient derivation and optimisation policy.

1. What does it mean for an LLM to learn?

A decoder-only language model is commonly trained to model a sequence as a chain of predictions conditioned on the preceding prefix. The model receives earlier tokens and estimates a distribution for the next one. During pretraining, the text itself supplies the targets: each next token is a training target without requiring manual annotation.

The Transformer architecture from chapter 01 and the self-attention operation from chapter 02 are already in place. Here we treat their weights as parameters θ. Learning means finding parameter values that reduce an objective over training examples. The optimiser does not add outside knowledge; it turns gradients into parameter updates.

Keep three layers of reasoning distinct:

  • Objective: which probability should increase, or which error should decrease?
  • Gradient: how does the objective change when a parameter changes?
  • Optimiser: how does the update combine gradients, learning rate, historical state and regularisation?

2. Next-token prediction: the autoregressive objective

For a token sequence x₁, x₂, …, xT, the probability of the joint sequence can be factorised using the chain rule:

pθ(x1, ..., xT) = ∏t=1..T pθ(xt | x1, ..., x(t-1))

The model learns to assign probability to the observed token conditioned on its prefix. Maximising sequence likelihood is equivalent to minimising its negative form, the negative log-likelihood (NLL):

L(θ) = - Σt log pθ(xt | x<t)

For minibatch optimisation and comparisons across lengths, the objective is commonly averaged over valid target positions. A mean reduction is an average per target token, not a sum over all tokens in the batch.

This is the basis of causal language modelling. The model builds a distribution over the vocabulary and receives a larger penalty when the observed token receives low probability. Capabilities that later emerge when using prompts are a separate question from the pretraining objective itself.

3. Shifting inputs and targets: the alignment that must be right

Consider this tokenised text:

tokens:  [The, model, learns, patterns, .]
input:   [The, model, learns, patterns]
target:  [model, learns, patterns, .]

The same sequence provides multiple training examples. At position 0 the model predicts token 1; at position 1 it predicts token 2, and so on. Inputs and targets have the same length after shifting by one position, but do not contain the same IDs at the same positions.

input_ids = batch[:, :-1]   # [B, T]
targets   = batch[:, 1:]    # [B, T]
logits = model(input_ids)   # [B, T, vocab_size]

The model processes the known prefix for each position. Causal masking prevents the state at position t from consulting later tokens, even though training computes outputs for all positions in parallel. This gives efficient computation without letting future answers leak into predictions.

Teacher forcing is not future leakage

During training, each position receives the correct corpus prefix, not previously sampled model predictions. This is commonly called teacher forcing. The causal mask is still essential: without it, a position could consult representations of tokens that should be unknown when making that prediction. During inference, the generated token is appended to the context to produce the next one.

A one-position alignment error changes the entire task: comparing each logit with the token already at that same position trains the model to do something else. The lab checks the shift before training starts.

4. Logits and Cross Entropy: measuring a prediction

The model's final projection returns a score for every vocabulary token. These are logits, not probabilities. For one position, z ∈ ℝᴠ, where V is vocabulary size. Softmax turns the scores into a distribution:

p_i = exp(z_i) / Σj exp(z_j)

If y is the correct class, Cross Entropy for that position is:

CE(z, y) = -log(softmax(z)[y])
         = -z_y + log(Σj exp(z_j))

The second expression matters for numerical stability: implementations can compute log-softmax using techniques such as log-sum-exp, without materialising a tiny probability and taking its logarithm afterwards. This is why torch.nn.CrossEntropyLoss expects unnormalised logits. Applying softmax first changes the scale and meaning of the loss; do not do it.

loss = F.cross_entropy(
    logits.reshape(-1, vocab_size),
    targets.reshape(-1)
)

With logits [B, T, V] and targets [B, T], batch and sequence dimensions are flattened so each of the B × T positions is treated as a classification over V classes. In batches with padding, invalid target positions must be excluded using ignore_index or an equivalent mask. Ignoring padding in attention alone is not enough if those targets still contribute to the loss mean.

What a lower loss actually means

Cross Entropy penalises predictions that assign little probability to the observed target. If the model assigns 0.8 to the correct token, the loss is −log(0.8), approximately 0.223. If it assigns 0.01, the loss rises to approximately 4.605. A useful loss does not require the correct token to be the argmax: it also measures the relative confidence assigned to that target.

Mean NLL in natural logarithms is related to perplexity by:

perplexity = exp(mean_negative_log_likelihood)

Perplexity is an exponential transform of loss, not a direct measure of understanding. Its value depends on tokenizer, evaluation set, token-counting convention and domain. Character-level perplexity cannot be compared directly with subword-level perplexity.

5. The Cross Entropy gradient: a signal for each logit

For a standard per-position Cross Entropy, the derivative with respect to logits has a compact form. If p is the softmax vector and y is the target index:

∂L/∂z = p - one_hot(y)

When averaging over N positions, the gradient is divided by N as well. The target coordinate has one subtracted from its predicted probability; the other coordinates retain their predicted probabilities. The result pushes the correct logit upwards relative to the others.

This derivative is only the first segment of backpropagation. Logits depend on the output projection; that projection depends on hidden representations; those representations pass through normalisation, residual paths, MLPs and attention. The chain rule propagates the signal to every matrix and embedding used in the forward pass.

The lab generates synthetic logits in float64, computes the derivative with autograd and compares it against the manual formula. The maximum absolute error is 1.39 × 10⁻¹⁷, consistent with floating-point rounding in this test.

6. Backpropagation: from error to parameters

Autograd builds a graph of differentiable operations during the forward pass. Calling loss.backward() makes PyTorch run reverse-mode automatic differentiation and accumulate in parameter.grad the derivative of the loss with respect to each parameter that requires gradients.

optimizer.zero_grad(set_to_none=True)
logits = model(input_ids)
loss = F.cross_entropy(
    logits.reshape(-1, vocab_size),
    targets.reshape(-1)
)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
optimizer.step()

Gradients accumulate by default. If they are not cleared before the next backward pass, they are added to the previous ones. zero_grad(set_to_none=True) leaves gradients as None until they are computed and can reduce memory writes compared with filling buffers with zeros.

The simplest gradient update is:

θ(t+1) = θ(t) - η · ∇θ L

η is the learning rate: it sets the step size. A gradient points locally towards increasing the objective; the negative sign moves parameters in a direction that locally reduces loss. In deep networks, gradient scales vary across parameters and steps, which is why adaptive optimisers and learning-rate policies are commonly used.

7. AdamW: adaptive moments and decoupled weight decay

Adam maintains exponential estimates of the first and second gradient moments. In simplified form:

m(t) = β1 · m(t-1) + (1 - β1) · g(t)
v(t) = β2 · v(t-1) + (1 - β2) · g(t)^2
m_hat = m(t) / (1 - β1^t)
v_hat = v(t) / (1 - β2^t)
θ ← θ - η · m_hat / (sqrt(v_hat) + ε)

The first moment smooths the gradient direction; the second estimates its scale per coordinate. Bias corrections compensate for both estimates starting at zero. Each parameter gets an update scale adapted to its history, but this does not remove the need to choose the global learning rate carefully.

AdamW separates weight decay from the gradient-based update. Intuitively, it combines Adam's adaptive step with a multiplicative contraction of parameters subject to decay:

θ ← θ - η · update_adam - η · λ · θ

This separation matters. Decoupled Weight Decay Regularization shows that, for adaptive optimisers such as Adam, adding an L2 penalty to the objective is not equivalent to applying decoupled weight decay. PyTorch implements AdamW with decay separated from the moment calculations.

Real training recipes do not necessarily apply decay to every tensor. A common setup groups parameters so weight matrices receive decay while biases and LayerNorm parameters do not. This is a configuration choice, not an automatic property of every implementation. The lab applies decay to linear matrices and excludes embeddings, biases and one-dimensional parameters.

A scalar check isolates the concept: with parameter 1, zero gradient, learning rate 0.1 and weight decay 0.2, AdamW leaves the parameter at 0.98. There is no loss gradient pushing the weight; the change comes from the decoupled decay term.

8. Learning-rate schedules: controlling step size

A constant learning rate is a simple baseline, but many training runs use a policy that changes η over time. Two common phases are:

  • Warmup: start with a small rate and increase it gradually over a configured number of updates.
  • Decay: after reaching the peak, reduce the rate so updates become progressively smaller.

Cosine decay moves from ηmax to ηmin along half a cosine wave:

η(t) = ηmin + 0.5 · (ηmax - ηmin) · (1 + cos(π · progress))

Progress moves from 0 to 1 during the decay phase. A preceding linear warmup can be written as:

η(t) = ηmax · (t + 1) / warmup_steps

The original Transformer paper popularised a schedule with warmup and inverse-square-root decay; cosine decay is another schedule family, not an exact reproduction of that recipe. PyTorch provides implementations such as LinearLR, CosineAnnealingLR and SequentialLR. In an update-based loop, the scheduler normally advances after optimizer.step(), following the contract of the specific API.

No schedule is best for every training run. Total token budget, architecture, batch size, initialisation, optimiser and dataset affect what works. A fair comparison keeps the other conditions fixed.

9. Gradient clipping and update stability

Global norm clipping computes a joint norm over gradients. If it exceeds a threshold c, all gradients are multiplied by the same factor so that the final norm does not exceed c:

scale = min(1, c / (||g||2 + ε))
g ← scale · g

This limits the gradient vector's magnitude before the optimiser uses it. It does not change the relative direction among parameter gradients, although it reduces their magnitude. In PyTorch, clip_grad_norm_ modifies gradients in-place and returns the total norm before clipping.

Clipping does not fix an incorrect mask, misaligned targets, a non-finite loss, an unsuitable learning rate or a data problem. It is a safeguard against excessive norms; logging the pre-clipping norm helps reveal how often the safeguard is activated.

10. Training loss, validation loss and generalisation

Training loss measures the objective on examples used to update parameters. Validation loss measures the same objective on held-out examples that do not take part in the backward pass. It helps monitor whether the model improves outside the data it directly optimises.

Training loss falling while validation loss stalls or rises can indicate overfitting. A small gap does not prove robust generalisation: it depends on dataset size and diversity, the split, tokenizer and whether examples are independent. Randomly splitting windows from one document can create context overlap; a serious evaluation should split by document or by a suitable temporal/domain boundary.

There is also a difference between pretraining and fine-tuning. Pretraining usually optimises the autoregressive objective over broad corpora. Fine-tuning adapts an existing model to a more specific distribution or objective, usually with a different dataset and budget. Loss values are not directly comparable when data, tokenizer or calculation changes.

Loss answers a narrow question: how much probability does the model assign to the real next tokens in this dataset? It does not by itself measure factuality, reasoning, safety, usefulness or deployed behaviour.

11. Reproduced laboratory: two optimisation policies

To move from theory to a controlled measurement, I built a small decoder-only model in PyTorch. It downloads neither a model nor a dataset. It uses a local copy of the Spanish technical corpus created for chapter 01 and trains on CPU.

The comparison uses two runs with identical initial weights, the same precomputed minibatch sequence and the same optimiser configuration. Only the learning-rate policy changes:

  • Constant: 5e-4 for all 240 updates.
  • Warmup + cosine: 24-step linear warmup, followed by cosine decay from 5e-4 to 5e-5.

Evaluation uses fixed windows: eight minibatches from training and eight from validation. Validation never takes part in a backward pass. This is enough for a reproducible teaching comparison, but it is not an exhaustive evaluation over every character in the split. To ensure the character-level encoding can represent every character in the corpus, the alphabet is built from both splits. This exposes the validation character inventory, but does not feed its examples into gradient updates. A production pipeline would fit its tokenizer on training data and explicitly define how unknown tokens are handled.

In this run, constant-rate AdamW finishes at validation loss 2.4630, while warmup + cosine finishes at 2.6363. This is not proof that a constant rate is generally superior. The schedule spends part of the budget below the maximum rate; with more updates, another dataset or a larger architecture, the relationship may change. The result shows why a chosen schedule should be measured rather than assumed to improve every run.

13. Common training mistakes

  • Unshifted targets: the model learns to reproduce the token it already sees instead of predicting the next one.
  • Softmax before Cross Entropy: a normalised distribution is passed where the function expects logits.
  • Accumulated gradients: zero_grad is omitted and updates accidentally mix previous minibatches.
  • Misaligned scheduler: scheduler.step is called in the wrong order or epochs are counted when the configuration is defined in updates.
  • Validation leakage: gradients are calculated on validation data or hyperparameters are repeatedly tuned against a set later presented as an independent test set.
  • Reading training loss only: training loss can fall while performance outside the fitting corpus gets worse.
  • Copying hyperparameters without context: paper values are not universal presets; global batch, tokens per update, architecture, precision and total budget matter.

14. What this laboratory does not demonstrate

The model has 62,880 parameters and operates at character level on a short technical corpus. It is not a replica of GPT-2, GPT-3 or a current production LLM. It does not measure conversational quality, emergent capabilities, reasoning, factuality, safety, GPU throughput, accelerator memory use or distributed scalability.

The comparison uses one seed, 240 updates per policy and a fixed evaluation sample. Robust evaluation would require multiple seeds, datasets and a larger budget, documented uncertainty and further optimisation controls. This micro-experiment cannot isolate how a schedule behaves on a large model.

What we can claim

The next-token objective is aligned and checked; the Cross Entropy derivative matches autograd; AdamW applies decoupled weight decay; clipping bounds the norm; and, in this specific comparison, both policies reduce loss, with constant learning rate lower after 240 updates. That is what the evidence measures, no more and no less.

15. What comes next

We now know how the model learns: the objective defines which token to predict, Cross Entropy turns logits into a signal, backpropagation distributes gradients, and AdamW turns that signal into updates.
