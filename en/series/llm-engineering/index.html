Not a prompt-engineering guide

This series covers language-model engineering from its internals to production operations. It is not a list of tools, launch news or shallow prompting examples. Each instalment must explain the mechanism, show tensor shapes, compare theory with an implementation and document limitations.

The route starts with Transformer architecture and progresses through training, inference, serving engines, quantisation, parallelism and evaluation. The goal is to help readers reason about bottlenecks, memory, latency, throughput, cost and design trade-offs.

Labs and evidence

The first experiment was run on a CPU-only host using PyTorch. It includes model code, a Spanish train/validation corpus, checkpoint, training log, metrics, loss curve, causal mask and attention maps. Measurements belong to the declared environment and are not presented as hardware benchmarks or results generalisable to large models.

Each future instalment will have its own lab where useful: mechanism unit tests, implementation comparisons, memory experiments and performance profiles. We will not label an experiment as reproduced when it has only been described on paper.

Technical standards for the series

  • Mechanism first: mathematics, tensor dimensions and dataflow before discussing frameworks.
  • Runnable code: small implementations to understand; real tools to validate.
  • Evidence: metrics, versions, hardware, configuration and visible limitations.
  • No false equivalence: a teaching TinyGPT is not a useful LLM; a loss curve is not intelligence; an attention map does not explain the whole model.
  • Primary sources: papers, official documentation, maintained repositories and results that can be checked.
