Path 01 · AI / LLMs

LLM Engineering — From Internals to Production

An eight-investigation technical sequence that starts with Transformer architecture and ends by measuring an inference service under load. Follow the recommended order: each stage uses concepts introduced earlier.

8 investigations8 labsAdvanced readingCPU is sufficient for the published labs

Stage 1 · Foundations and training

01–03 · Understand the model
01

Inside a Transformer

Start with tokens, embeddings, Q/K/V projections, causal masking and decoder blocks. Build a mental model of the data flow before studying optimisation or serving.

Read investigation ↗TinyGPT lab ↗
02

Self-Attention Deep Dive

Derive scores, softmax, weighted sums and the backward pass. Then compare MHA, MQA and GQA and see what changes when Keys and Values are shared.

Read investigation ↗Attention lab ↗
03

How an LLM Learns

Connect next-token prediction to shifted targets, Cross Entropy, backpropagation, AdamW, learning-rate schedules and validation.

Read investigation ↗Training lab ↗
Stage goal: explain the forward pass, gradients and parameter updates of a small Transformer.

Stage 2 · Inference and serving

04–05 · Turn the model into a service
04

Inference: Prefill, Decode and KV Cache

Separate prompt processing from incremental generation. Calculate KV memory and understand why inference can become compute- or memory-bandwidth-bound.

Read investigation ↗Inference lab ↗
05

vLLM: PagedAttention and Continuous Batching

Move from an isolated forward pass to concurrent requests: KV blocks, block tables, prefix caching, scheduling, chunked prefill and backpressure.

Read investigation ↗Serving simulator ↗
Stage goal: understand how memory, admission control and scheduling affect latency and throughput in an LLM service.

Stage 3 · Optimisation, scale and measurement

06–08 · Engineering decisions
06

LLM Quantization

Compare FP16, BF16, FP8, INT8 and INT4, scales, granularity, outliers and calibration, and the trade-offs between memory, bandwidth and error.

Read investigation ↗Numerical simulator ↗
07

Distributed LLM Inference

Study Tensor Parallelism, Pipeline Parallelism, NCCL collectives, Ring AllReduce and the impact of NVLink, PCIe and multi-node topology.

Read investigation ↗Distributed simulator ↗
08

Benchmarking: TTFT, TPOT and Throughput

Finish with a reproducible methodology: open-loop and closed-loop load, percentiles, coordinated omission, goodput, SLOs and trace analysis.

Read investigation ↗Trace analyser ↗
Stage goal: reason about compression, parallelism and performance without confusing numerical simulations with real-hardware benchmarks.
Path 02 · Infrastructure / IT Operations

Systems & IT Operations — Diagnostics and operations

A practical path around three operational problems: measure a server before intervening, control a runtime change and diagnose tempdb log growth. This is a recommended thematic order, not a strict prerequisite chain.

Advanced Windows Server Performance Diagnostics

Build a timeline and correlate CPU, memory, storage and networking. Learn when PerfMon is enough and when ETW, WPR and WPA are needed.

Stage 2 · Control changes safely

02 · PowerShell
02

Enterprise migration to PowerShell 7.6 LTS

Separate PowerShell 7 from Windows PowerShell 5.1, inventory installations and dependencies, validate compatibility and plan deployment and rollback.

Stage 3 · Diagnose a specific cause

03 · SQL Server
03

SQL Server tempdb: log growth caused by an open transaction

Establish a baseline, reproduce the scenario on an isolated instance, identify ACTIVE_TRANSACTION, quantify autogrowth and verify space reuse after rollback.

Path 03 · Resilience & Recovery

Resilience & Recovery — Design, test and demonstrate recovery

An engineering path to define recovery objectives, test dependencies, measure outcomes and close exercises with traceable evidence. Start with the methodology and extend it with service-specific tests.

2 published investigations2 offline labsRTO · RPO · testing · evidence

Stage 1 · Design and measure a DR exercise

01 · Test engineering
01

Design a Disaster Recovery Test and Measure Service Recovery

Define scope, RTO/RPO, dependencies, milestones, functional tests, acceptance criteria, cleanup and continual improvement. Includes an offline scorecard for timestamps and evidence.

Read investigation ↗Download Recovery Test Scorecard ↗
The scorecard analyses manually entered data; it does not run restores or failover, or independently validate recovered-data integrity.

Stage 2 · Operate test failover and failback

02 · DR operations
02

A Disaster Recovery Test Failover and Failback Runbook: Isolation, Validation and Controlled Return

Separate an isolated exercise from a production switchover and return. Define approvals, isolation, dependencies, gates, abort, data reconciliation, cleanup and evidence.
