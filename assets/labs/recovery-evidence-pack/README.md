# Recovery Evidence Pack Builder — Lab 03

An offline Python tool that validates a structured DR exercise record, fingerprints referenced evidence files with SHA-256, and generates an evidence register plus an editable After-Action Report / Improvement Plan (AAR/IP) draft.

## Run it

Requires Python 3.10+ and the standard library only. No network access or third-party packages are required.

```bash
python evidence_pack.py samples/exercise.json --evidence-dir samples/evidence --out evidence-pack-out
python -m unittest discover -s tests -v
```

A successful run writes manifest.json, manifest.sha256, evidence-register.csv, AAR-IP.md and validation-report.json. The tool references source evidence in place; it does not copy, modify, encrypt, sign, timestamp or retain original evidence files.

## Critical limits

**A SHA-256 hash is not a digital signature, trusted timestamp, immutable record store or forensic chain of custody.** It enables later comparison against the fingerprint generated by this tool. If an operator replaces both an artefact and its manifest, the tool alone cannot establish which version is authentic. Collection time, source, collector role and descriptions are operator-supplied metadata.

For controlled enterprise records, retain originals in an approved evidence repository with role-based access, retention controls, audit logging, versioning or immutability where required, and independent approval. Follow classification, privacy, retention, legal-hold and incident-handling rules.

The output is not a compliance certificate and does not prove that an exercise occurred, that an observation is accurate, that an action is effective or that the service is recoverable. An evaluator and accountable service owner must review and approve the AAR/IP before distribution.

All sample names, timestamps, event data and evidence files are synthetic.
